# Постоянная база Neon для Dota Spread

Код уже поддерживает PostgreSQL. После подключения каталог, ордера, очередь и паузы Steam будут храниться отдельно от Render и сохраняться после перезапуска сайта. Без `DATABASE_URL` приложение продолжает использовать временную SQLite.

## Подключить базу к существующему сайту

1. Открой [Neon Console](https://console.neon.tech/) и зарегистрируйся. Можно использовать вход через GitHub.
2. Создай проект `dota-spread` на тарифе **Free**. Выбери ближайший доступный регион к Render, например Frankfurt. Оставь созданную базу `neondb` и основную ветку.
3. Нажми **Connect**. Выбери базу `neondb`, роль владельца базы и **Connection pooling**, если переключатель доступен. Скопируй **только строку подключения**, начинающуюся с `postgresql://` или `postgres://`. Не копируй команду `psql`, кавычки, `DATABASE_URL=` или строку для JavaScript. Сохрани параметры SSL из выданной строки.
4. Открой [Render Dashboard](https://dashboard.render.com/), выбери существующий сервис **dota-spread → Environment → Add Environment Variable**.
5. **Key:** `DATABASE_URL`. **Value:** скопированная строка Neon. Другие переменные оставь прежними; `COLLECTOR_ROLE` по умолчанию `all`.
6. После завершения сборки новой версии выбери **Save and deploy**. Если новая версия ещё не собралась, выбери **Save, rebuild, and deploy**. Дождись статуса **Live**.
7. Открой [проверку сайта](https://dota-spread.onrender.com/api/health). В ответе должны быть `storage.backend: "postgresql"`, `storage.persistent: true`, `storage.state: "ok"` и `collector_running: true`. Таблицы создаются автоматически — выполнять SQL вручную не нужно.

Строка подключения содержит пароль. Вставляй её непосредственно в Render Environment; не добавляй в GitHub, фронтенд, `render.yaml`, чат или скриншоты.

При первом подключении новой базы цены собираются заново. После следующих перезапусков сохраняются котировки и прогресс проверки. Старые цены сохраняют исходное время и показываются по прежним правилам свежести, а не становятся свежими после перезапуска.

## Как работают несколько сборщиков

Каждый сборщик подключается к **той же базе** через `DATABASE_URL`. Предмет получает временную бронь на 180 секунд; для скачивания большого каталога — 600 секунд. Если процесс остановился, бронь истечёт и работу заберёт другой процесс. Ответ из истёкшей или заменённой брони не перезапишет новую котировку.

Пока независимость лимитов Steam не подтверждена, у всех сборщиков **общая пауза и общий темп**: один запрос Steam одновременно, пауза после ответа. Дополнительные сборщики дают резерв при остановке процесса, но не умножают лимит Steam. Ограничение одного сборщика сохраняется в базе и соблюдается остальными.

Возможные роли:

| `COLLECTOR_ROLE` | Поведение |
|---|---|
| `all` | Сайт, каталог Lis-Skins, курс и очередь Steam. Текущий режим, одного сервиса достаточно для начала. |
| `sources` | Каталог Lis-Skins и курс. Очередь Steam обслуживают отдельные сборщики. |
| `steam` | Только очередь ордеров Steam. |
| `none` | Сайт читает базу; все источники обновляют отдельные процессы. |

На сервере отдельный сборщик запускается командой:

```sh
python -m backend.worker
```

Ему нужна та же `DATABASE_URL`; роль по умолчанию `steam`. Для сборщика каталога задай `COLLECTOR_ROLE=sources`. Нельзя запускать несколько отдельных серверов с собственными SQLite и ожидать общей очереди. На Render отдельные Background Workers требуют платного тарифа; их создание не включено в текущий Blueprint. Для начала оставь существующий веб-сервис с ролью `all`.

## Лимиты бесплатного размещения

У Neon Free есть месячные лимиты вычислений и передачи данных. На момент подготовки инструкции — 100 CU-часов и 5 GB исходящего трафика на проект в месяц; при исчерпании этих лимитов вычисления приостанавливаются до следующего периода или смены тарифа. Для непрерывной работы минимального вычислителя 0.25 CU это примерно 400 часов в месяц. Бесплатный Neon не означает неограниченный сбор 24/7. Актуальные условия: [Neon plans](https://neon.com/docs/introduction/plans).

Данные в базе не удаляются при засыпании вычислителя Neon. Если Render засыпает, сборщик тоже остановлен; база сохраняет его прогресс. Если база временно недоступна во время работы сайта, API отдаёт последние данные из памяти с отметкой ошибки обновления. Сборщик возобновляет обращения после восстановления базы.

Источники: [подключение Neon](https://neon.com/docs/get-started/connect-neon), [переменные Render](https://render.com/docs/configure-environment-variables), [Render Free](https://render.com/docs/free).
