# Dota Spread

Сканер цен Dota 2: React + TypeScript + Vite на фронтенде, Flask на бэкенде. Сравнивает минимальную доступную цену покупки на Lis-Skins с **самым высоким ордером покупки Steam**, вычитает комиссии Steam и показывает положительную разницу.

## Публичная версия

Пошаговая инструкция бесплатной публикации: [PUBLISH.md](PUBLISH.md). В проекте есть `Dockerfile`, `render.yaml` с тарифом Free и запуск через Gunicorn. Фронтенд и API размещаются одним сервисом. На Render Free сборщик останавливается во время сна сервиса, а SQLite используется как временный кэш.

## Запуск

На macOS открой `start.command` двойным щелчком или выполни в папке проекта:

```sh
./start.command
```

Нужны Python 3.11+ и Node.js 22.12+ либо 24+. Скрипт установит отсутствующие зависимости, соберёт фронтенд и запустит приложение на **http://127.0.0.1:5050**. Оставь терминал открытым. Остановка — Ctrl+C. Это локальный сервер разработки, не публичный хостинг.

Ручной запуск после установки зависимостей:

```sh
.venv/bin/python -m backend.app
```

Для разработки интерфейса во втором терминале:

```sh
cd frontend
npm run dev
```

Vite работает на http://127.0.0.1:5173 и перенаправляет `/api` во Flask на порту 5050.

## Возможности

- Реальные цены и ордера; выдуманные или демонстрационные сделки отсутствуют.
- Переключение USD/RUB, поиск, фильтры по цене, проценту выгоды и количеству предметов по лучшему ордеру.
- Сортировка по проценту, сумме выгоды, цене и свежести.
- Избранное сохраняется в браузере. В нём отображаются только актуальные выгодные предложения.
- CSV-экспорт отображаемой выборки с исходной валютой и временем котировки.
- Настройка комиссии пополнения Lis-Skins. По умолчанию 0%; для полной стоимости укажи комиссию своего способа оплаты.
- Сохранение каталога и ордеров в SQLite, статусы источников и таймеры повторных попыток. Устаревшие положительные оценки остаются с меткой «Ожидает проверки» до 30 минут; свежие сделки считаются отдельно.

## Расчёт и валюты

`Выгода % = (сумма на баланс Steam − полная стоимость покупки) / полная стоимость покупки × 100`.

Комиссии Steam для Dota 2: 5% площадке и 10% издателю. Они начисляются на сумму продавца. Используется обратный расчёт в целых центах с минимумом в один цент для каждой комиссии и округлением вниз. Поэтому при большой сумме ордер 1380 даёт примерно 1200 на баланс, а не 1380 × 0,85. На дешёвых предметах минимумы существенно влияют на процент.

Steam может вернуть публичный стакан в валюте региона сервера; параметр `currency=1` не гарантирует USD. Адаптер **проверяет фактическую валюту** ответа. В текущем окружении Steam возвращает EUR. Ордер и сумма после комиссии пересчитываются в USD по официальным курсам USD/EUR Банка России. USD/RUB в интерфейсе — отображение этих нормализованных котировок; RUB **не означает отдельный рублёвый стакан Steam**. Курс ЦБ является ориентиром и может отличаться от курса Steam и платёжного провайдера. Процент оценки зависит от выбранной схемы конвертации. Исходная цена видна в карточке предмета и CSV.

Выручка поступает в кошелёк Steam, а не на банковский счёт. Ордер может исчезнуть или изменить цену до сделки. Возможность продажи также зависит от ограничений конкретного предмета и аккаунта. Это сканер предложений, не гарантия исполнения и не торговый бот.

## Частота обновления

Экран запрашивает последний результат каждые **10 секунд**. Один процесс Flask содержит отдельные потоки для каталога и Steam: скачивание большого каталога не останавливает проверку ордеров. HTTP-запросы Steam выполняются последовательно, с паузой по умолчанию 4 секунды после каждого ответа.

Полная выгрузка Lis-Skins содержит сотни тысяч предложений. Её читаем потоково и сводим к минимальной цене и наличию по точному названию. По умолчанию выгрузка проверяется каждые 60 секунд. При неизменном ETag используем условный запрос и ответ 304 без повторного скачивания и разбора. Время получения ответа не подменяет время цен `last_update` из источника. Из каталога исключаются дополнительные камни, стили и предметы с будущим/непонятным сроком разблокировки, для которых недостаточно сопоставления названий.

Ордера Steam проверяются очередью. Пока есть новые предметы, два из трёх слотов выделяются им, один — перепроверке ранее найденных выгодных позиций, если с их проверки прошло не менее 60% срока свежести. Свежие ордера не запрашиваются повторно каждые 10 секунд. Счётчик проверенных предметов включает также ответы об отсутствии подходящего ордера. Очередь и паузы сохраняются в SQLite между перезапусками с сохранённым кэшем. Полное обновление тысяч предметов за 10 секунд с этим публичным источником не обеспечивается. Для такого охвата потребуется источник массовых котировок с разрешённой частотой и достаточными лимитами.

Свежими считаются ордера не старше 120 секунд и цены каталога не старше 600 секунд. Порог каталога учитывает фактически наблюдаемую задержку генерации выгрузки более трёх минут. Возраст цены виден у источника. Эти пороги приходят из API и одинаково применяются сервером и браузером. После их истечения последние положительные оценки остаются до 30 минут с меткой «Ожидает проверки» и временем котировки; они не входят в число свежих выгодных сделок. При новом ответе без ордера, исчезновении предмета из каталога или неположительной оценке строка убирается. CSV содержит статус и оба времени источников.

HTTP 429/403 вызывает паузу от пяти минут. Повторные ограничения увеличивают паузу (до часа, а более длинный `Retry-After` также соблюдается) и интервал запросов. Поддерживаются числовой и календарный `Retry-After`. Один успешный запрос не сбрасывает весь режим восстановления; темп возвращается постепенно после серии успешных ответов. В интерфейсе виден таймер следующей попытки. Эти настройки снижают нагрузку, но не гарантируют отсутствие внешних ограничений Steam. Пауза экрана останавливает только его обновление.

Переменные окружения:

| Переменная | По умолчанию | Значение |
|---|---:|---|
| `PORT` | 5050 локально / 10000 в Gunicorn | Порт веб-сервера; на Render назначается платформой |
| `UPDATE_INTERVAL` | 10 | Интервал цикла, минимум 10 сек. |
| `STEAM_BATCH_SIZE` | 3 | Размер окна выбора очереди; повышение не ускоряет плавный сбор |
| `STEAM_REQUEST_INTERVAL` | 4 | Пауза после ответа Steam, минимум 2 сек.; при ограничении растёт автоматически |
| `LIS_REFRESH_INTERVAL` | 60 | Период проверки большой выгрузки, минимум 10 сек. |
| `QUOTE_TTL` | 120 | Максимальный возраст ордера, сек. |
| `CATALOG_TTL` | 600 | Максимальный возраст цены Lis-Skins для свежей сделки, сек. |
| `PENDING_TTL` | 1800 | Срок показа последней оценки с отметкой ожидания, сек. |
| `DOTA_DB_PATH` | `.cache/market.sqlite3` | Файл локальной базы |

Изменение лимитов сбора не увеличивает допустимые лимиты внешнего источника. При изменении `PORT` нужно также изменить адрес прокси в `frontend/vite.config.ts` для Vite.

## Проверка

```sh
.venv/bin/python -m unittest backend.test_market -v
cd frontend
npm run build
```

Тесты проверяют комиссии и минимумы, пересчёт валют, точное сопоставление предметов, ликвидность лучшего ордера, исключение устаревших и неподходящих предметов, паузу при лимитах, сохранение цен и валидацию API. Сетевые источники не вызываются в тестах.

## Источники и структура

- [Официальная выгрузка Lis-Skins Dota 2](https://lis-skins.com/market_export_json/api_dota2_full.json).
- Публичные страницы предметов [Steam Community Market](https://steamcommunity.com/market/): стакан берётся из данных `valve-ssr-data`. Это адаптер сайта, не стабильный документированный Steam Web API; изменение структуры страницы потребует обновления `providers.py`.
- [XML-курсы Банка России](https://www.cbr.ru/development/SXML/).
- [Правила и комиссии Steam](https://help.steampowered.com/en/faqs/view/61F0-72B7-9A18-C70B).

`backend/providers.py` получает котировки, `pricing.py` считает деньги, `service.py` обновляет и фильтрует данные, `store.py` сохраняет их, `app.py` отдаёт API и собранный фронтенд. `frontend/src/App.tsx` содержит интерфейс; `styles.css` — адаптивное оформление.

Для публичного размещения используй подготовленный Docker-образ и Gunicorn. Конфигурация запускает один веб-воркер с одним сборщиком. При увеличении числа процессов сборщик нужно вынести отдельно. Не публикуй встроенный Flask-сервер разработки напрямую.
