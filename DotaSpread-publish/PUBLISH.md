# Публикация на GitHub + Render Free

Нужны аккаунты [GitHub](https://github.com/) и [Render](https://dashboard.render.com/). Сайт будет доступен по публичной HTTPS-ссылке Render; покупать домен не нужно. Docker на своём компьютере устанавливать не требуется: образ собирает Render.

## 1. Создай репозиторий GitHub

1. Открой [создание репозитория](https://github.com/new).
2. Назови его `dota-spread`. Видимость кода — Public или Private, на твой выбор; публичность сайта от неё не зависит.
3. Не добавляй автоматически README, `.gitignore` или лицензию: исходные файлы проекта уже подготовлены.
4. Нажми **Create repository**.

## 2. Загрузи исходники

Для первой загрузки подготовлен архив `.cache/publish/DotaSpread-publish.zip` в папке проекта. Распакуй его двойным щелчком. В нём только исходники и настройки публикации.

1. В пустом репозитории нажми **uploading an existing file**. В уже заполненном — **Add file → Upload files**.
2. Перетащи **содержимое распакованной папки** в область загрузки, сохранив папки `backend` и `frontend`. Сам ZIP загружать не нужно.
3. На Mac сочетание **Cmd + Shift + .** показывает скрытые `.gitignore` и `.dockerignore`, чтобы их тоже можно было выбрать.
4. Подтверди загрузку кнопкой сохранения коммита (**Commit changes** / **Propose changes**, в зависимости от интерфейса). Для нового пустого репозитория добавляй файлы прямо в основную ветку.
5. Проверь, что `Dockerfile`, `render.yaml`, `gunicorn.conf.py`, `backend` и `frontend` находятся на верхнем уровне репозитория, а не внутри дополнительной папки `DotaSpread-publish`.

Если загружаешь рабочую папку напрямую, не выбирай `.venv`, `node_modules`, `frontend/dist`, `.cache`, `.git` и `.env`. В подготовленном архиве их нет.

## 3. Подключи Render

1. Открой [Render Dashboard](https://dashboard.render.com/), зарегистрируйся или войди.
2. Нажми **New → Blueprint**.
3. Подключи GitHub и разреши Render доступ к репозиторию `dota-spread`.
4. Выбери этот репозиторий, основную ветку и путь Blueprint **`render.yaml`**.
5. Назови Blueprint `dota-spread`. Проверь, что создаётся один **Web Service** с тарифом **Free**.
6. Нажми **Deploy Blueprint**. Render установит зависимости, соберёт React и запустит Flask через Gunicorn. Отдельные Build Command и Start Command вводить не требуется.
7. После успешной сборки открой созданный сервис. Его адрес `https://…onrender.com` — публичная ссылка на сайт. Точный адрес назначит Render.

Инструкция соответствует [официальному процессу Blueprints](https://render.com/docs/infrastructure-as-code). Если не хочешь использовать Blueprint, создай **New → Web Service** из этого же репозитория: Language **Docker**, Dockerfile Path **`./Dockerfile`**, Instance Type **Free**, Health Check Path **`/api/health`**. Остальные команды запуска уже в Dockerfile. Создавай сервис одним из этих способов, чтобы не получить дубликат.

## 4. Проверь сайт

- Статус сервиса должен стать **Live**.
- Открой `/api/health` по адресу сайта: ожидаются `status: "ok"` и `collector_running: true`.
- На главной сначала может быть загрузка: кэш цен не переносится с компьютера, источники проверяются заново. Предложения появятся после получения каталога, курса и выгодных ордеров.
- Если источник отвечает ошибкой, посмотри его статус в интерфейсе и вкладку **Logs** сервиса. Доступность Steam/Lis-Skins из дата-центра проверяется уже после публикации.

## 5. Сохрани цены и очередь после перезапуска

Подключи внешнюю PostgreSQL по [инструкции Neon](NEON.md): создай базу Free, скопируй строку подключения в Render Environment как `DATABASE_URL` и выполни Save and deploy. Таблицы создаются автоматически. Проверка `/api/health` должна показать `storage.backend: "postgresql"` и `storage.persistent: true`. Пока переменная не задана, постоянная база не подключена.

## Бесплатный тариф и обновления

Render Free засыпает после 15 минут без входящих запросов. В это время сборщик остановлен; при следующем заходе запуск занимает примерно минуту. Локальная SQLite-база без `DATABASE_URL` — временный кэш, который теряется при сне, рестарте и публикации новой версии. С внешней PostgreSQL котировки и прогресс сохраняются. Включённый лимит составляет 750 часов на рабочее пространство за месяц. Есть также лимиты сборок, трафика и исходящих обращений; интенсивный сбор может привести к приостановке сервиса. Подробности: [Render Free](https://render.com/docs/free).

Экран запрашивает API каждые 10 секунд, пока сервис активен. Большой каталог Lis-Skins проверяется раз в 60 секунд независимо от Steam. Ордера Steam запрашиваются очередью, с паузой 4 секунды после ответа и увеличением паузы при ограничениях. Полный каталог не обновляется за 10 секунд. Тариф без сна потребуется для непрерывного сбора без посетителей.

Устаревшие положительные оценки остаются до 30 минут с меткой «Ожидает проверки». Порог свежести ордера — 120 секунд, цены Lis-Skins — 600 секунд. Возраст берётся из самого источника; успешная повторная загрузка не делает старую цену новой.

Для сбора с домашнего Mac без платного API используй [LOCAL-COLLECTOR.md](LOCAL-COLLECTOR.md). После подключения к той же Neon сайт переводится в `COLLECTOR_ROLE=none`; тогда `collector_running: false` в его проверке здоровья ожидается, поскольку сбор идёт на компьютере.

Если исходники загружены внутрь `DotaSpread-publish`, в **Settings → Build & Deploy** задай **Root Directory** `DotaSpread-publish`, **Dockerfile Path** `./Dockerfile`, **Docker Build Context Directory** `.`. Для Blueprint внутри такой папки задай в определении сервиса `rootDir: DotaSpread-publish`.

После изменения кода загружай обновлённые исходники в подключённую ветку GitHub: Render автоматически пересоберёт сайт. Архив для первой публикации является снимком исходников на момент его создания и не обновляется сам.

## Как устроен запуск

`Dockerfile` собирает фронтенд в Node.js 24, затем запускает бэкенд в Python 3.14. `backend/wsgi.py` создаёт приложение и включает сборщик по `COLLECTOR_ROLE` (по умолчанию `all`). `gunicorn.conf.py` задаёт публичный адрес `0.0.0.0:$PORT`, один веб-процесс и четыре потока. Общая PostgreSQL координирует задания и обращения к источникам. Для отдельных сборщиков и роли `none` используй [NEON.md](NEON.md); текущий Blueprint дополнительных платных процессов не создаёт.

Для проверки контейнера на компьютере с работающим Docker:

```sh
docker build -t dota-spread .
docker run --rm -p 10000:10000 dota-spread
```

После запуска открой `http://127.0.0.1:10000`.
